# Дорожная карта процесса внутреннего аудита

Это утверждённая модель декомпозиции. Каждая будущая DRAKON-схема описывает
только одну задачу из этого порядка. Схемы получают результаты предыдущей
задачи из общего хешированного журнала запуска и не повторяют в тексте чужие
действия.

```text
1. Выбрать цель
2. Подключиться к цели
3. Найти живые хосты во всех разрешённых CIDR компании
4. Выполнить этап «нет учётных данных»
5. Записать результаты через API и завершить запуск
```

## 1. Выбор цели

Вход: очередь задач панели.

Результат: занятая задача, IP VPN-цели, утверждённый SHA схемы, граница
компании, список разрешённых CIDR и запреты. Если чего-либо нет — статус
`blocked`, дальнейшие задачи не запускаются.

## 2. Подключение к цели

Вход: результат выбора цели.

Результат: VPN подключён, существует `ppp0`, маршруты сохранены, а
управляющий маршрут Kali не направлен через `ppp0`. При ошибке — `dead` или
`blocked`, VPN отключается.

## 3. Поиск живых хостов

Вход: активный VPN и разрешённые CIDR.

Результат: список живых хостов и coverage по всем разрешённым CIDR компании.
Это отдельная контрольная точка: активный поиск начинается только после
разрешения оператора для точного SHA схемы.

## 4. Нет учётных данных

Вход: список живых хостов, coverage и отдельное разрешение этапа.

Цель: найти минимальный подтверждённый доступ без переданных учётных данных:
доступный сервис, безопасно читаемую метаинформацию, анонимно доступный ресурс
либо подтверждённую небезопасную конфигурацию.

Разрешены только шаблоны команд из утверждённого в панели раздела MITRE для
этапа «нет учётных данных» и только в пределах задачи. «Все команды MITRE» не
означает произвольную технику из справочника. Для каждой команды необходимы
проверка границы, лимит времени, доказательство и статус coverage.

Запрещены: передача или подбор паролей, эксплуатация, изменение состояния,
массовая выгрузка данных, перехват трафика и повтор команд после ошибки без
нового разрешения.

Результат: подтверждённые факты о сервисах, шарах, анонимном доступе или
отсутствии такого доступа; каждый факт связан с хостом, портом, техникой MITRE
и доказательством.

## 5. Запись через API и завершение

Вход: результаты этапов 3 и 4.

Результат: через API записаны хосты, сервисы, шары, coverage, доказательства
и итог запуска. Учётные данные, если они законно обнаружены как результат
разрешённой проверки, не записываются в схемы, Git или открытый журнал:
передаётся только защищённая ссылка на хранилище секретов и доказательство
факта. После записи VPN отключается, `ppp0` исчезает, а управляющий маршрут
остаётся вне VPN.

## Правило исполнения

Воркёр и агент выполняют только текущую схему и не выбирают следующий этап
самостоятельно. Переход к следующей схеме возможен лишь по результату
предыдущей в общем журнале и при требуемом разрешении оператора.
